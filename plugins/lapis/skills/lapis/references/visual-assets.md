# Visual assets

Use this file when an image, icon family, or supplied asset set leaves a direction or layout choice
open. Put source facts in `sources` and `claims.known`, inferred uses in `claims.proposed`, and
blockers in `claims.unresolved`. Use the existing asset ledger for shipped assets, not a new record
format. Candidate access and acquisition remain subject to `lzl-research`'s limits and source policy.

## Image job

Name what the image must help the reader understand before looking for it:

| Job | Candidate evidence | Wrong substitute |
|---|---|---|
| prove a product feature | current product view or detail | atmosphere hiding the feature |
| teach an operation | labeled sequence or process close-up | illustration without actionable detail |
| establish conditions | documented environment | interchangeable lifestyle stock |
| compare options | matched scale, angle, and light | crops that bias comparison |
| supply atmosphere | authored image or texture | mood presented as capability evidence |

Describe the actual object, action, environment, and production variables, not only mood.
If removal leaves a claim unsupported, the image must be current and traceable. Use none when
no image improves the task. Compare candidates on real content in the direction or layout
`explorations` they settle; do not create a new exploration decision kind for assets.

## Crop and set

For each shipped slot, state the focal point, protected detail, text-safe area, and source variant
in `claims.proposed`, naming the existing ledger asset id. These are prose, not new ledger fields.
Compare real crops, including the narrow one: a mechanism, complete silhouette, or face that proves
the claim must not disappear. A different mobile composition is art direction, not a smaller file.
Keep a set coherent through light, distance, grade, background, and crop rhythm. Different media
can coexist with distinct named layers. Never grade product color, documentary evidence, or skin
tone to fit the palette.

## Icons

Build a contact sheet from actual navigation, actions, objects, states, and domain concepts.
Compare semantic clarity, state pairs, small-size counters, apparent stroke beside text,
directionality, and delivery. Catalog size does not establish semantic coverage. Keep the existing
family unless a test fails. One missing concept may need a visible label or a matched local glyph,
not a second family. Compare optical mass in real controls, not equal view boxes; distinguish the
visible glyph from its hit area. Label uncertain metaphors. Include the contact sheet in any
direction `explorations` it settles; the chosen family, size, and stroke stay in `tokens.icons`.

Specify mirror, fixed, or localized behavior per glyph; never flip a whole family for RTL.
If delivery uses a symbol font, test its unavailable-font and ligature path in the real control.
Pin the exact package, upstream collection, version, and applicable notices in existing records;
an aggregator's label grants neither glyph rights nor site access. Brand marks identify the actual
service, not the user's identity or an implied partnership. Native symbols stay within the
verified platform/delivery agreement. The control's programmatic state owns selection or expansion,
not the icon's fill; decorative glyphs beside sufficient visible text need no duplicate name.

## Supplied asset sets

Separate an observed asset fact, an inferred relation with its sample limit, and a proposed use.
Extract only choice-changing grammar: silhouette, occupied area, edge/stroke, light, material,
crop, sequence, and contrast. Classify disagreements as authority, role, variant, grammar,
permission, or accessibility; current owner guidance outranks a convenient file. Prove one slice
with real copy and states before spreading an inference. A sampled color is not an approved
identity value. Preserve official artwork; do not trace a governed mark or replace it with similar type.
