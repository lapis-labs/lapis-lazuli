# Email and host-controlled surfaces

Use this file for delivered email or an interface inside a host that owns rendering, navigation,
permissions, and updates. A template preview is not delivered-message evidence; a webview is not
necessarily a browser. Preserve the sending/hosting system rather than adding capabilities.

## Delivered email

Keep essential information, reading order, and action URLs useful without images, custom fonts,
media queries, or decorative CSS. Use live text and meaningful anchors; sensitive commitments go
to the product's trusted authenticated surface. A plain-text part preserves the same essential
information and destinations. Layout tables are presentation scaffolding; actual invoice or other
data tables retain headers and data semantics.

Separate required presentation from enhancements with usable fallbacks. Sending systems may inline,
rewrite, sanitize, or track markup, so inspect the delivered message. Choose the client matrix from
recipient and support evidence, not a generic provider census. Exercise narrow/wide windows,
images blocked, text enlargement, supported light/dark transformations, localized long strings,
RTL and reading order where promised, and actual destination/expiry/recovery behavior.

Do not put essential prices, codes, states, or actions only in imagery. Web-font failure must leave
readable script-complete text with acceptable metrics, including Hangul, kana/Han, Latin and numbers
where required; a family name in a stack is not delivered-face evidence. Avoid fixed text heights.
Client dark modes may invert some colors but not images; test marks and text on real resulting
backgrounds. One client screenshot does not establish dark-mode or delivery support.

Sent, delayed, bounced, expired, already used and forwarded messages have distinct consequences.
Use supplied resend, address correction and recovery policy; do not invent instant arrival or a
security-sensitive operation performed directly by the message.

## Host boundary

Identify which host owns Back, close, history, external destinations, authentication/session,
message bridges, files/downloads, permissions, safe areas, keyboard and error recovery. Do not
assume browser chrome, password management, popups or new windows exist. Define priority between
web history, modal dismissal and native navigation so Back neither traps the person nor unexpectedly
exits. Keep the full task reachable through the host's supported route.

A bridge or host API is a capability, not authorization. Keep origins and data scope with the
existing product policy; no automatic account connection, permission request or external write.
Widgets, extensions and other constrained hosts need their actual update/input limits checked,
not a reduced copy of an app screen. Report the exact host/client and exercised states.
